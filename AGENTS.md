# Project instructions

- Use [Conventional Commits 1.0.0](https://www.conventionalcommits.org/en/v1.0.0/#specification) for every commit that contains a code change. Write subjects as `<type>[optional scope]: <description>`; use `feat` for features, `fix` for bug fixes, and `!` or a `BREAKING CHANGE:` footer for breaking changes.
- Keep code clean, modular, and human readable. Prefer straightforward names and small functions; reuse existing code and avoid unnecessary abstractions or dependencies.
- Keep changes within the approved scope and verify behavior that the change affects.
